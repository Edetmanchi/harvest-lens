# HarvestLens

**Seedling Insight, Harvesting Success.** Turns fragmented agricultural data into decisions for policymakers, and connects farmers with buyers.
One Next.js app, with Neon Postgres as the only data store (files, jobs, sessions, rate limits and the audit log all live there).

- **Lens:** Data Studio (upload → map → clean → review → publish, with a full audit trail), the insight dashboard (Harvest Story, Map, Storage & Credit, Insights, Priority), state profiles, the Act-First Priority Index, rule-based recommendations, and PDF/CSV/Excel exports.
- **Market:** seller profiles, listings with photos, search, contact reveal, inquiries, saved-search alerts, wanted requests, ratings, reports, verification and moderation.
- **The loop:** the map's supply layer shows aggregated listings against loss and food-insecurity layers.

## Quick start

```bash
npm install
cp .env.example .env.local        # then fill DATABASE_URL (a Neon dev branch) and BETTER_AUTH_SECRET
npm run db:migrate                # drizzle-kit migrations: PostGIS, pg_trgm, schema, search triggers
npm run db:seed                   # reference data, 37 state boundaries, rules, weights, super admin, sample datasets
npm run dev
```

Sign in with `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`. Without `RESEND_API_KEY` or `TERMII_API_KEY`, emails and SMS OTP codes are printed to the server log.

> **Sample data is synthetic.** `npm run db:seed` loads two datasets marked *(SAMPLE)*. They are generated by `scripts/generate-sample-data.ts` and calibrated to the PRD headline figures (300.01M t produced, 72.70M t lost 2019–2024; 59.6% no storage; 62.5% no credit), but the per-state and per-crop values are **not real NBS data**. Before launch, upload the team's cleaned NBS dataset in Data Studio, then unpublish the samples or seed with `SEED_SAMPLE_DATA=false`.

## Architecture

```
app/(marketing)   landing, about, methodology, data sources, legal pages
app/(auth)        login (email + phone OTP), register, onboarding, invitations, password reset
app/(app)         dashboard/*, states/[slug], studio/*, market/*, admin/*, account, notifications
app/api           auth, upload (4 MB chunks), files/[id], export/*, geo/states, cron, health
lib/db            Drizzle schema (all PRD tables), reference data, seed geometry
lib/pipeline      parse (SheetJS/Papa), map (synonyms + Levenshtein), normalise (aliases, units, years), outliers (IQR)
lib/jobs          Neon job queue (FOR UPDATE SKIP LOCKED, 5,000-row batches, checkpoints, 3 retries) + handlers
lib/scoring       Act-First Priority Index, recommendation rules, scenario simulator
lib/analytics     visibility-scoped, cached aggregation (tag "analytics", revalidated on publish)
lib/market        search (FTS + pg_trgm), supply/price aggregates (min group 5), photo processing (sharp → WebP ≤ 300 KB)
```

- **Jobs** start immediately with `after()` and are swept every minute by Vercel Cron (`vercel.json` → `/api/cron`, authenticated with `CRON_SECRET`).
- **RBAC** is enforced in `proxy.ts` (signed-in gate), then again in every page (`requirePageRole`), Server Action and Route Handler (`requireRole`).
- **Rate limits** (fixed window, `rate_limits` table) cover sign-in, sign-up, OTP, password reset, contact reveal, search, uploads and exports.
- **Audit log** records sign-ins, publishes, rollbacks, exports, contact reveals, role changes, moderation and admin edits.

## Environments (OPS-1)

Use one Neon project with a branch per environment: `dev`, `staging`, `production`, plus a branch per PR created by CI (`.github/workflows/ci.yml`; set `vars.NEON_PROJECT_ID` and the `NEON_API_KEY`, `E2E_ADMIN_PASSWORD` and `E2E_AUTH_SECRET` secrets). Each Vercel environment gets its own `DATABASE_URL`.

## Status against the PRD

This build covers Milestones 1–3 and much of Milestone 4. **Not done yet** (needs a decision or an external dependency):

- **Postgres row-level security** as a second layer (PRD §10). Organisation scoping is enforced in every query (`visibilitySql`), but RLS policies are not written yet.
- **LGA-level map (DASH-9).** The schema supports LGAs, but no LGA boundary data is loaded.
- **Scheduled email reports (REP-4), offline dashboard (P2), feature-flag UI (OPS-9), load test (OPS-10).** Feature flags are seeded as data only.
- **Translations.** The switcher and Pidgin/Hausa/Yorùbá/Igbo files exist, but only navigation and the landing hero are drafted, and they need review by native speakers. A lightweight cookie-based i18n is used instead of next-intl.
- **Sentry.** Errors are posted to Sentry's store endpoint when `SENTRY_DSN` is set; the full `@sentry/nextjs` SDK is not installed.
- **Legal pages** are drafts pending legal review, as the PRD requires.

See `docs/runbook.md` for the recovery runbook (OPS-5).
